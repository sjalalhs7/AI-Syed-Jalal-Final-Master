# V135 — SJ Arena: the Arena.ai-style battle clone, built into this app

Date: 4 November 2026 · Base: `main` @ `60ea13a` (V134.1) · Repo: `sjalalhs7/AI-Syed-Jalal-Final-Master`

## The ask

> "Clone of ArenaAi also add in this project please."

Arena.ai is a side-by-side model battle: one prompt, several engines answer, you vote blind, and a
leaderboard forms from real results. This release adds that as a **first-class page inside the
existing application** — not a screenshot, not a second app, not a mock.

## What "clone" honestly means here

Arena.ai's public product runs many proprietary models. This project has **five working local engines**
and **four catalogued cloud engines that need the owner's server-side keys**. So the clone reproduces
the *product mechanics* exactly — same prompt fan-out, blind cards, vote, judge breakdown, artifacts,
history, leaderboard — while refusing to invent the part it cannot do:

| Arena mechanic | V135 implementation | Proof |
| --- | --- | --- |
| One prompt, N models | `POST /api/arena/battles` runs 2–4 contenders on the identical prompt | `server/tests/arena.test.mjs` |
| Blind answers | Engines are stored, but `engine`, `label` and `kind` are stripped from the payload until the vote | test asserts `engine === null` and `label /^Engine [A-D]$/` |
| Judge with reasons | `sj-rubric-v1`, deterministic bands (structure 20 / specificity 25 / coverage 25 / honesty 15 / code 15), sub-scores shown per answer | `JUDGE.disclaimer` printed on the page |
| Human outranks judge | The vote is stored separately (`decided_by='user'`); agreement with the judge is reported, never overwritten | vote test |
| Leaderboard | Elo-style ratings, start 1200, ±12 per decided battle, clamped 100–3000, **per account** | leaderboard test + UI |
| Artifacts | Fenced code is extracted; HTML/SVG render in a sandboxed `iframe srcdoc` | `extractArtifacts` test |

**Unconfigured engines are never a tie and never a win.** A cloud engine without a key is stored as
`status='not_configured'`, `score:0`, `nonAnswer:true`, with the reason printed in the card; the judge
withholds a verdict when fewer than two engines actually answered.

Three separate rules make that true rather than aspirational:

1. **Status beats prose.** The judge treats any stored status other than `ok` as a non-answer, so an
   engine's own error text can never be scored as if it were an answer (`judgeVerdict`).
2. **Local tools refuse open-ended work.** General local tools return `needsProvider`; that is stored as
   `needs_provider` — a labelled non-answer — instead of a template that could win on length.
3. **No rating credit without an answer.** A vote for a side that produced nothing is rejected server-side
   and, defensively, an unanswered engine can never gain rating from anyone else's vote.

## Shipped

### Engine + judge — `frontend/functions/arena.mjs` (new)
Nine contenders, a deterministic rubric judge, artifact extraction, and Elo helpers. One
implementation shared by the API and the tests, so the page and the contract cannot drift.
Each local contender runs **its own profile** (`plan:` / `critic:` / `code:` / `analyze:`) so a battle
between four local engines is four different answers, not four copies of whichever keyword the prompt
happened to start with. V135 also adds the missing local `analysis` profile, so the Analysis Advisor
answers honestly instead of silently falling through to "not connected".

### Routes — `frontend/functions/arena-routes.mjs` (new)
```
GET    /api/arena/catalogue          public: engines, availability, judge, rubric, limits
GET    /api/arena/battles            account: history (limit, optional ?mode=)
POST   /api/arena/battles            account: run 2–4 engines on one prompt → 201
GET    /api/arena/battles/:id        account: reopen a battle (revealed if voted/revealed)
POST   /api/arena/battles/:id/vote   account: a|b|c|d|tie — once only (409 on repeat)
POST   /api/arena/battles/:id/reveal account: reveal early; records "no longer blind"
DELETE /api/arena/battles/:id        account: owner-only delete
GET    /api/arena/leaderboard        account: ratings, W/L/T, judge agreement
```
Local engines run **in-process** through the same `localAssistant` the platform uses; cloud engines go
through the real `/api/ai/run` route. Rate limited (12 battles / minute) and CSRF-protected like every
other write.

### Data — `backend/db/migrations/011_v135_arena.sql` (+ `schema.sql` mirror)
`arena_battles`, `arena_responses`, `arena_artifacts`, `arena_ratings`. Additive and replay-safe;
readiness now requires **19** tables (was 15), so a half-migrated database cannot report ready.

### Page — `frontend/arena.html`, `assets/arena.css`, `assets/arena.js` (new)
Battle builder with engine availability tags, attachments (≤3 text/code files), blind cards A–D,
per-answer rubric bars and notes, vote bar, judge breakdown, sandboxed artifact previews, account
leaderboard, and battle history. Linked from the homepage nav, the guide, Agent Studio and Agent Lab.
The service worker cache moved to `aj-v135-shell` and the private page is excluded from precache.
On the static GitHub Pages copy the page says it cannot run battles instead of faking them.

## Honesty section (printed on the page)
- The judge is a **deterministic rubric**, not a human reviewer and not a second AI model.
- Rating = your recorded preference plus the rubric, **not** a benchmark of model quality.
- Blinding hides the label, not the style — tone can still give an engine away.
- Local engines work with no key; cloud engines are labelled until the owner configures and verifies a key.
