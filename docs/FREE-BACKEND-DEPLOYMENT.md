# Free backend deployment checklist

## Current architecture
- Frontend: Cloudflare Pages (`https://ai-syed-jalal-live.pages.dev/`).
- API: Node.js ESM service in `source/AI-Syed-Jalal-FINAL-RECOVERED/backend/`.
- Database: external PostgreSQL; the API requires a real `DATABASE_URL` before database-backed login/session features can work.
- `render.yaml` defines a free Render Docker web service and points the Docker build context at `source/AI-Syed-Jalal-FINAL-RECOVERED`, which is required because the backend Dockerfile copies both `backend/` and `config/` from that directory.

## Deploy steps
1. In Render, create a Blueprint from this GitHub repository and select branch `recovery/data-upgrade-2026-10-22`.
2. Create a free PostgreSQL database on Neon. Copy its pooled or direct connection string as recommended by Neon for the application.
3. When Render prompts for `DATABASE_URL`, paste the Neon connection string into the secret field. Do not commit it to GitHub or share it in chat.
4. Confirm `CSRF_SECRET` is generated by Render, `PGSSL=true`, and `PGSSL_REJECT_UNAUTHORIZED=true`. Keep `CORS_ORIGIN` restricted to the real frontend origin; add any additional trusted origin explicitly as a comma-separated value only if required.
5. Deploy and wait for the Render health check `/api/health` to pass. Save the generated `https://...onrender.com` URL.
6. Test `/api/health`, then the database diagnostics and login flows in a private test account. Do not mark login or AI as live until database, provider keys, and browser tests pass.
7. Only after the API has a stable public URL, update the frontend API base URL in a separate change and deploy to a preview first. Keep the current production Pages deployment untouched until preview checks pass.

## Important limitations
- Render free services may sleep when idle and can have a cold-start delay.
- A successful process health check does not prove database connectivity, login, sessions, or live AI providers are configured.
- Provider API keys are optional for deployment but required for their corresponding live AI features. Set them as Render secrets, never in source control.
- This repository change only adds deployment configuration and instructions. It does not create a Render account/service or Neon database, and it does not produce a live API URL by itself.
