### Additional observations

- No non-example private-key/provider-key matches were found in project-owned application paths by the targeted scan. This was not a full secret scan of every imported upstream file or Git object, and pattern matches are not proof that a credential is valid.
- The imported upstream tree is large and is not equivalent to maintained application code. Its licenses, training data, dependency lifecycle scripts and runtime behavior require separate review before redistribution or execution.
- The updated published ZIP's GitHub metadata reports the checksum recorded in the existing updated `.sha256` file. A local byte/CRC audit of that separate asset was blocked by the asset CDN; only the original parts received a full local reconstruction/CRC audit.
- GitHub reported successful source-check runs for the later revision, but direct local execution exposed the stale aggregate gates above. A green workflow summary is not a substitute for checking which suites actually ran and reproducing the intended release command.

## Changes made on the audit branch

- Added `recovery-manifest.json`: exact sizes and SHA-256 for every part and the reconstructed archive, plus inventory and known identical case-variant counts.
- Added `scripts/verify_recovery.py`: streaming verification, CRC checks, safe inventory validation, optional non-overwriting output/extraction, portable handling of declared identical case variants, and no execution of archive contents.
- Added 23 offline regression tests covering corruption, missing/truncated inputs, checksum mismatch, unsafe paths/links, duplicate/case collisions, inventory failures, non-overwrite behavior and cross-filesystem publication.
- Hardened the Windows batch merger and added Ubuntu/Windows CI with read-only repository permission and pinned action revisions.
- Removed one-time source extraction/push and stale Wikipedia overwrite automation from this control branch.
- Added `.gitignore`/`.gitattributes` for local recovery outputs, Python caches, batch line endings and binary parts.
- Corrected README, release handoff, security guidance and status documents.
