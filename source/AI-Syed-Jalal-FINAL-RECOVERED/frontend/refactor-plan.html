ENGINEERING DECISION RECORD · 4 NOVEMBER 2026

One runtime, four front doors

“Merge everything” is only safe if you can name what is genuinely shared. This record states the decision taken for each surface, the evidence behind it, and what still counts as duplication. Where a merge would have hidden an honest limit, it was refused on purpose.

Decisions

One row per decision, with the reason and what would reverse it.
  1. merged

    One agent runtime behind JalalAi, JARVIS and Agent Studio

    Shared: frontend/functions/agent-runtime.mjs

    Evidence: four published tools, one planner, one bounded executor, one persisted trace. JalalAi and the JARVIS console both POST /api/assistant/chat; there is no second implementation to drift.

    Reverse only if a surface needs a tool the others must not have — then publish it in AGENT_TOOLS first, so the trace stays truthful.

  2. merged

    One remembered voice across every read-aloud surface

    Shared: assets/speech-preferences.js + frontend/functions/voice-surfaces.mjs

    Evidence: JalalAi, JARVIS, Agent Studio and the Workspace dock resolve their voice through one module and one storage key; the self-check fails if a surface stops doing so.

    Add a surface by extending VOICE_SURFACES, never by wiring a private voice selector.

  3. merged

    One evidence chain: run → trace → self-check → review

    Shared: agent_runs, agent_self_checks, expert_reviews, audit_events

    Evidence: every claim the pages make is backed by a row this deployment wrote, which is why the Expert Critic can grade it instead of repeating marketing copy.

    A new capability must write its evidence before it appears on a page.

  4. separate

    Arena stays a separate page, on purpose

    Not merged into: JalalAi chat

    Reason: a battle compares two engines blind and stores both responses plus a deterministic verdict. Folding it into chat would show the answers to the author before the vote, which destroys the blind comparison that makes the result meaningful.

    Keep it separate. Share the runtime, share the voice, share the evidence — not the interaction.

  5. separate

    Workspace and dashboard stay operational, not conversational

    Not merged into: the assistant

    Reason: record CRUD, approvals and user administration are multi-step forms with their own permissions and history. Replacing them with a chat box would remove the reviewable approval queue the compliance story depends on.

    They link to the assistant instead of imitating it.

  6. remaining

    Two chat renderers still exist

    Duplication: assets/jalalai.js and assets/jarvis.js

    Both render messages and a trace. They differ in voice behaviour and in which evidence they emphasise, so they are duplicates in layout but not in behaviour. This is a real, bounded duplication — not a hidden one.

    Next step: extract a shared renderTrace() and addMessage() into assets/trace-view.js. Do it with the browser journeys green, not before.

  7. remaining

    Two knowledge adapters ship the same Wikipedia code

    Duplication: backend/knowledge/wikipedia.mjs and frontend/functions/wikipedia-adapter.mjs

    Necessary: the Cloudflare build only bundles frontend/, so the adapter has to exist inside the Functions tree. The copies are byte-identical and both are covered by tests.

    Replace with a build step that copies one source of truth, or move the adapter to a shared package.

  8. refused

    Merging the cloud providers into one “AI” toggle was refused

    Rejected: a single provider switch

    Reason: the four adapters have different keys, models, error shapes and cost. One toggle would hide which provider actually answered, and the product's whole position is that it never hides that.

    Keep the explicit provider selector and the “key configured; live call not yet verified” label.

What this record does not claim

  • That there is no duplication left. Two remain, named above, with a next step for each.
  • That the merge is finished for all time. The contract files are the guard rail, not a promise.
  • That a shared runtime makes the surfaces equivalent. They share execution, not permission: each page states what its own mode can do.
